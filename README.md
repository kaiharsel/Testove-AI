# AI-обробка звернень

Тестове завдання на позицію Junior IT / AI Developer: внутрішній інструмент служби підтримки, у якому можна зберігати звернення клієнтів і аналізувати їх за допомогою LLM.

**Живе посилання:** https://testove-five.vercel.app

## Що зроблено за ТЗ

- [x] **Додати звернення** — форма «імʼя клієнта + текст звернення», дані зберігаються в базу (Postgres на Neon)
- [x] **Список звернень** — усі збережені звернення, лишаються після перезавантаження сторінки
- [x] **Кнопка «Аналізувати (AI)»** — викликає LLM і повертає структурований результат окремими полями:
  - пріоритет: низький / середній / високий
  - категорія: оплата / доставка / скарга / технічна проблема / повернення / інше
  - короткий підсумок в одне речення
  - чернетка відповіді клієнту
- [x] **Результат аналізу зберігається** в базі й показується на картці звернення
- [x] **Next.js + TypeScript**
- [x] **Справжній аналіз**, а не захардкоджений: кожне натискання — реальний запит до моделі
- [x] **Простий і охайний дизайн**
- [x] **Деплой на Vercel**

## Що зроблено додатково

**Робота зі зверненнями**
- Фільтр за категорією (випадаючий список з лічильниками) і перемикач «Спочатку важливі» — сортування за пріоритетом
- Плашка «Нове» для звернень, створених за останню годину; нові й старі звернення розділені в списку
- Видалення звернення з вікном підтвердження
- Автовизначення мови звернення (плашка UA / EN) і AI-переклад звернення на іншу мову; чернетка відповіді пишеться мовою клієнта
- Повторний аналіз («Переаналізувати») і кнопка «Копіювати» для чернетки відповіді
- Окрема сторінка «Нове звернення»: після збереження сторінка плавно прокручується до щойно створеної заявки й підсвічує її

**Інтерфейс**
- Бокова навігація, на телефоні — бургер-меню
- Світла й темна тема (за замовчуванням як у системі, вибір запамʼятовується)
- Українська та англійська мови інтерфейсу; AI пише підсумок і чернетку відповіді мовою інтерфейсу
- Сповіщення про події: збереження, аналіз, видалення, копіювання, зміна теми та мови
- Індикатор прогресу під час AI-аналізу
- Адаптивна верстка, власний скролбар, SVG-іконки

**Надійність**
- Відповідь моделі обмежена JSON-схемою й додатково перевіряється через Zod перед збереженням — у базу не потрапить неповний чи неправильний результат
- Автоматичний перехід на запасні моделі, якщо основна перевантажена або недоступна
- Параметризовані SQL-запити (захист від SQL-інʼєкцій), валідація довжини полів на сервері
- Ключі зберігаються лише у змінних середовища, у репозиторій не потрапляють

## Як працює AI-аналіз

1. Кнопка «Аналізувати (AI)» викликає серверну дію `analyzeTicketAction` — ключ до LLM ніколи не потрапляє в браузер
2. Сервер надсилає моделі текст звернення з інструкцією (правила пріоритету, перелік категорій, вимоги до відповіді)
3. Модель зобовʼязана відповісти за JSON-схемою (`responseJsonSchema` у Gemini, `tool_choice` у Claude), тому результат завжди приходить окремими полями, а не суцільним текстом
4. Відповідь перевіряється через Zod і зберігається в базу

Провайдер обирається за наявним ключем: `GEMINI_API_KEY` або `ANTHROPIC_API_KEY`.

**Чому Gemini, а не Claude чи ChatGPT:** у Gemini є безкоштовний ліміт без привʼязки картки, а API Claude та OpenAI для цього тестового потребували б оплати. Інтеграцію з Claude я теж реалізував: вона вмикається одним ключем `ANTHROPIC_API_KEY`, без змін у коді.

## Структура

```
src/
  app/
    page.tsx            сторінка «Звернення»
    new/page.tsx        сторінка «Нове звернення»
    actions.ts          серверні дії: створення, аналіз, видалення
    TicketCard.tsx      картка звернення з аналізом
    TicketList.tsx      список, фільтр, сортування
    ...                 навігація, тема, мова, сповіщення
  lib/
    db.ts               робота з базою
    analyze.ts          запит до LLM і валідація відповіді
    i18n.ts             переклади
scripts/
  seed.mjs              приклади звернень для демо
```

## Запуск локально

Створити `.env.local`:

```
DATABASE_URL=postgresql://...
GEMINI_API_KEY=...
```

```bash
npm install
npm run dev      # http://localhost:3000
npm run seed     # необовʼязково: додати приклади звернень
```

Таблиця `tickets` створюється автоматично при першому запиті.

## Деплой

Vercel → імпорт репозиторію → додати змінні середовища `DATABASE_URL` і `GEMINI_API_KEY` → Deploy.

## Проблеми, які довелося вирішувати

**Модель недоступна.** Перший запит до `gemini-2.5-flash` повернув 404: модель уже недоступна для нових користувачів. Після заміни моделі почав приходити 503: безкоштовна модель була перевантажена. Я подивився логи сервера, отримав через API список доступних моделей і зробив так: основна модель — аліас `gemini-flash-latest` (завжди актуальна версія), а при помилках 404 / 429 / 5xx додаток автоматично пробує запасні моделі.

**Повідомлення «зависало».** Після збереження звернення сповіщення не зникало, а прокрутка до нової заявки не спрацьовувала. Причина: сайт очищав адресу сторінки від службового параметра, це перерендерювало компонент і скасовувало всі його таймери. Я відвʼязав таймери від адреси сторінки, і обидві проблеми зникли.

**Встановлення залежностей.** Два паралельні `npm install` зіпсували `node_modules` (помилка `ENOTEMPTY`). Вирішилось повним видаленням папки й одним чистим встановленням.
